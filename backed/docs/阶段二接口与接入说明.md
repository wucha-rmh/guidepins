# 阶段二后端：登录与私人地图

本阶段交付认证、数据库会话和地图元数据管理。后端保留原有地市、公共地图、图钉和底图读取接口；图钉编辑、攻略出处、下载和前端登录界面按后续阶段推进。

## 1. 模块职责

| 模块 | 职责 |
| --- | --- |
| `auth/controller` | 注册、登录、会话恢复、退出和 CSRF 令牌接口；校验输入、设置 Cookie |
| `auth/service` | 密码核验、普通账号注册、七天固定会话及过期清理 |
| `auth/security` | 当前请求身份恢复与会话 Cookie 读写 |
| `config` | 集中配置 Spring Security、CSRF、密码编码器与时钟，并提供 PostgreSQL UUID 类型处理器 |
| `common` | JSON 统一响应类型，以及安全过滤器、容器错误分派共用的响应输出等公共代码 |
| `auth/mapper` | 账号和会话的数据库访问；原始会话令牌不落库 |
| `publicmap` | 公共查询、我的地图、创建、改名及公开状态切换；统一检查地图权限 |
| `city`、`basemap` | 地市目录与底图文件读取，沿用既有职责 |

组件依赖继续使用 `@Autowired`。Mapper 接口、实现、数据库行与 XML 沿用现有分层，不另建重复的账号、权限或私人地图模块。

## 2. 运行前置条件

1. 已有的五张业务表和 UUID 默认值保持不变。
2. 先核对并完成账号的 `avatar_path`、`status` 增量。原 SQL 见[账号头像与状态增量迁移](../../docs/技术/账号头像与状态增量迁移.md)，成功执行过则不要重复执行。
3. 按[应用账号授权](阶段二数据库接入.md)创建专用运行账号。`guidepins_agent` 保持只读用途。
4. 在现有 `backed/.env` 中保留地址、密码等已有配置，按实际值修改以下项，不覆盖整个文件：

```properties
GUIDEPINS_DB_USER=guidepins_app
GUIDEPINS_DB_PASSWORD=应用账号的独立密码
# 本地 HTTP 开发使用 false；正式 HTTPS 环境必须为 true。
GUIDEPINS_COOKIE_SECURE=false
```

默认 Cookie 配置为 `Secure=true`；在本地使用 HTTP 且没有显式设置为 `false` 时，浏览器不会按正常 HTTPS 方式携带此 Cookie。生产站点应通过 HTTPS 同源代理 `/api` 和 `/maps`。

从 `backed` 目录执行 `mvn spring-boot:run`。后端通过数据库默认 UUID 与 `INSERT ... RETURNING` 取得新增账号、地图主键；Hikari 已允许写事务，实际权限由专用账号控制。

## 3. 认证与 CSRF 对接

登录会话 Cookie 名为 `GUIDEPINS_SESSION`，路径 `/`，使用 `HttpOnly`、`SameSite=Lax` 和可配置的 `Secure`。会话绝对有效期为七天，不自动续期。每次登录创建独立会话；退出只删除当前会话。数据库只保存 32 字节随机令牌的 SHA-256 摘要。

每次鉴权都关联读取账号当前角色和状态。`status=0` 的账号不能登录，已有会话也不能继续作为登录身份使用。无效或过期 Cookie 在公共读取中作为访客处理；要求登录的接口返回 401。禁用账号不会自动隐藏它的公开地图。

所有 POST、PATCH 等写请求（包括注册、登录、退出）都必须通过 CSRF 校验：

1. 同源请求 `GET /api/auth/csrf`，浏览器保存 `GUIDEPINS_CSRF` Cookie。
2. 从 JSON 的 `data` 中读取 `headerName` 和 `token`，写请求使用这个请求头和值；不要读取或自行拼接 CSRF Cookie。
3. 登录成功或退出后会清除旧 CSRF Cookie，下一次写请求前重新获取令牌。
4. 缺失或无效 CSRF 返回 403。即使尚未登录，写请求也会先经过 CSRF 校验；通过校验后再按接口要求返回 401。

同源前端的最小调用例子：

```javascript
async function csrfHeaders() {
  const response = await fetch('/api/auth/csrf', { credentials: 'same-origin' });
  if (!response.ok) throw new Error('获取请求令牌失败');
  const { data: csrf } = await response.json();
  return { 'Content-Type': 'application/json', [csrf.headerName]: csrf.token };
}

const response = await fetch('/api/auth/login', {
  method: 'POST',
  credentials: 'same-origin',
  headers: await csrfHeaders(),
  body: JSON.stringify({ email: 'alice@example.com', password: '用户输入的密码' }),
});
// 登录成功后，下一次写请求重新调用 csrfHeaders()。
```

这里使用 Spring Security 默认的掩码 CSRF 令牌与 Cookie 仓库，参考[官方 CSRF 文档](https://docs.spring.io/spring-security/reference/6.5/servlet/exploits/csrf.html)。不启用跨域凭据访问，也不使用浏览器 localStorage 保存登录令牌。

## 4. 接口

所有 JSON 接口统一返回以下三个字段。`code` 与 HTTP 状态码一致，数据在 `data` 内；失败响应的 `data` 为 `null`，`message` 为可向用户展示的信息。PMTiles 文件继续使用二进制与 Range / 206，不包装成 JSON。

```json
{"code":200,"message":"查询成功","data":[]}
```

```json
{"code":401,"message":"请先登录","data":null}
```

普通查询／操作成功为 200，创建账号／地图成功为 201；参数错误 400、未登录 401、CSRF 或权限拒绝 403、不可见／不存在 404、数据冲突 409、服务器异常 500。方法不支持 405、响应格式不支持 406、请求内容类型不支持 415 同样使用统一外层。未知异常不返回内部异常消息、SQL 或堆栈。

下表所述“返回身份、列表、详情、记录”均指 `data` 的内容。退出接口返回 200（不再使用无响应体的 204）：`{"code":200,"message":"退出成功","data":null}`。

服务端统一使用 `common.ApiResponse` 的静态方法创建响应；控制器返回业务数据时，由 `config.ApiResponseAdvice` 自动调用对应入口：

```java
ApiResponse.success(code, message, data);
ApiResponse.error(code, message);
```

| 方法与地址 | 登录要求 | 请求与响应 |
| --- | --- | --- |
| `GET /api/auth/csrf` | 无 | `data` 为 `{headerName, token}`，同时设置防伪 Cookie |
| `POST /api/auth/register` | 无，需 CSRF | 邮箱或手机号与密码；成功 201，返回本人身份，不自动登录 |
| `POST /api/auth/login` | 无，需 CSRF | 同上；成功 200，返回本人身份并设置登录 Cookie |
| `GET /api/auth/me` | 需要 | 返回当前身份；未登录、过期或禁用返回 401 |
| `POST /api/auth/logout` | 无，需 CSRF | 无请求体；成功 200，返回“退出成功”，删除当前会话并清除两个 Cookie，可重复调用 |
| `GET /api/cities` | 无 | 原地市目录接口 |
| `GET /api/cities/{cityId}/maps` | 无 | `data` 为该地市公开地图数组 |
| `GET /api/maps/{mapId}` | 公开地图无需登录 | `data` 为包含图钉的地图详情；私人地图只允许所有者读取 |
| `GET /api/me/maps?cityId={uuid}` | 需要 | 该地市下属于本人的全部地图，按更新时间降序、UUID 排序 |
| `POST /api/cities/{cityId}/maps` | 需要，需 CSRF | `{name, visibility?}`；默认私人，成功 201，返回地图管理记录 |
| `PATCH /api/maps/{mapId}/name` | 需要，需 CSRF | `{name}`；成功 200，返回地图管理记录 |
| `PATCH /api/maps/{mapId}/visibility` | 需要，需 CSRF | `{visibility}`；成功 200，返回地图管理记录 |
| `GET /maps/{code}.pmtiles` | 无 | 六位城市代码，保留 HTTP Range / 206 行为 |
| `GET /api/cities/{code}/boundary` | 无 | 该地市市界 GeoJSON（`application/geo+json`，缓存一天） |

注册和登录每次只填写邮箱、手机号中的一项：

```json
{"email":"alice@example.com","password":"输入至少六个字符的密码"}
```

```json
{"phone":"+8613800000000","password":"输入至少六个字符的密码"}
```

邮箱去除首尾空白并整体转为小写；手机号去除首尾空白后必须带国家码，符合 E.164 形式。注册密码 6～128 个 UTF-16 代码单元，不去除首尾空白；登录兼容已有账号的较短密码，最多 128 个代码单元。不验证登录标识所有权，不提供绑定、合并或找回密码。

身份响应字段为 `id`、`email`、`phone`、`role`、`avatarPath`、`createdAt`，不会返回密码编码、原始会话令牌或其摘要。新账号固定为 `user`，头像默认 `null`，状态默认正常；头像上传与账号管理页面未包含在本阶段。

地图名称先去除首尾空白，长度 1～120 个 UTF-16 代码单元；`visibility` 仅允许 `private`、`public`。管理记录字段为：

```json
{
  "id": "地图UUID",
  "cityId": "地市UUID",
  "name": "秦淮散步",
  "ownerId": "本人账号UUID",
  "visibility": "private",
  "createdAt": "2026-11-24T08:00:00Z",
  "updatedAt": "2026-11-24T08:00:00Z"
}
```

客户端不能指定 `role`、`status`、`ownerId`、`id`、创建或更新时间；这些未知输入字段返回 400。接口时间为 UTC ISO 8601，前端显示时再按北京时间转换。

## 5. 地图访问规则

| 操作 | 访客 | 普通用户 | 管理员 |
| --- | --- | --- | --- |
| 读取公开地图与图钉 | 允许 | 允许 | 允许 |
| 创建地图、我的地图 | 401 | 仅本人 | 仅本人 |
| 读取私人地图 | 404 | 仅所有者 | 仅所有者 |
| 修改地图名称 | 401 | 仅所有者 | 本人地图及他人的公开地图 |
| 切换公开状态 | 401 | 仅所有者 | 仅所有者 |

不存在与不可见统一返回 404；地图可读但无写权限返回 403。图钉 SQL 自身也关联地图检查权限。写 SQL 检查数据库中当前账号状态、角色、归属与地图公开状态，不依赖客户端或旧页面的权限判断。

名称或公开状态实际变化时，在同一事务中更新 `updated_at`；原值重复提交保留原时间。读取、登录、无效输入、权限拒绝和事务回滚不改变地图时间。地图创建时两个时间相等。
